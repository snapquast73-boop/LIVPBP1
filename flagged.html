3 · How each value on the site is checked

The page-level check is tests/official-e2e.mjs. It fetches the official endpoints below, loads each published page from disk with that page's own <script src> files, routes the page's fetch to the official response bodies, and then compares what the page rendered with what MLB reported. No expected value in that file is typed in by hand.

Official endpointWhat the check asserts against itSource
Schedule, hydrate=team,linescore,decisions,review One scoreboard card per game; team names, scores, W-L records, venue, status, and W/L/S decisions exactly as reported; tab counts equal the slate counts. /api/v1/schedule
Live game feed Header teams/score/status, every linescore inning and R/H/E/LOB total, every play description in order with its inning and score, every batter's AB/R/H/RBI/BB/SO and every pitcher's IP/H/R/ER/BB/SO. /api/v1.1/game/{gamePk}/feed/live
Review records in the live feed One Challenges & Reviews card per reviewDetails record, the badge count, ABS outcome wording from isOverturned, and counter lines that quote the official review / absChallenges numbers. feed/live (ABS sample, game 822974)
Game-status registry Which codes count as a challenge/review, taken from the registry instead of matching the words in a description. /api/v1/gameStatus
Event-type registry The official-scorer-pending codes, os_ruling_pending_primary and os_ruling_pending_prior, both described “Official Scorer Ruling Pending”. /api/v1/eventTypes
Filter tabs on the Replay Feed The All tab excludes ABS rows and the ABS tab contains exactly the official ABS records, matching the uploaded README. uploaded README

A check that never runs against these endpoints cannot claim parity with MLB data. The CI workflow .github/workflows/check.yml runs this test on every pull request, on every push to main, and on a nightly schedule; .github/workflows/live-check.yml drives the deployed site end to end in a real browser (tests/live-e2e.mjs) after each Pages deployment.

7 · Request budget and terms
  • The StatsAPI is keyless and permits “individual, non-commercial, non-bulk use”. Every page pauses when the tab is hidden and backs off on HTTP 429. See docs/api-compliance.md.
  • MLB.com's Terms of Use restrict automated collection beyond personal, non-commercial home use. This is a personal fan project with no ads, analytics or resale; it is not affiliated with MLB.
  • Values shown are read from the official response at request time. A saved page, a screenshot or a cached tab can be out of date — the linked MLB endpoint is the authority for any specific value.

6 · Additional flagged irregularities
  • Live MLB data changes continuously. Every figure is point-in-time. Passing CI certifies the response the check downloaded, not any future response. An unavailable feed is not evidence that no review occurred; a failed or partial scan labels its totals stale/partial instead of presenting old numbers as current.
  • Review classification is inference from reported codes. Rows are grouped using MLB's reported reviewType and the official gameStatus registry codes; the ABS code (MJ) is confirmed against MLB's own ABS highlight, other codes are shown as reported rather than given a more specific label. This classification is not an official MLB ruling field.
  • “Runs at risk” and the score trackers are computed, not reported. The Before / Possible-after tracker and the ⚠️ Runs-at-Risk banner are derived from the reviewed play's own scoring movements. A “possible” score is explicitly not a prediction — on a boundary review MLB may instead place runners.
  • Public reuse of MLB data is not asserted here. The StatsAPI is a public endpoint but this page makes no claim about permission or terms for redistribution. The site is an unofficial fan project and states that it is not affiliated with MLB or MLB Advanced Media.
  • Exact parity with the original author's private implementation cannot be proven. The upstream repository named by the inherited README, buffedlizard55-lab/MLB-Live-PBP, returns HTTP 404 through the GitHub API (re-verified 2026-11-22), so the true original cannot be compared against. Parity is anchored to the maintainer-identified working copy (LIVPBP2), whose HTML matches this upload apart from the flagged-footer link.
  • Sound and desktop notifications cannot be verified headlessly. The controls are wired and the chime is synthesised in the browser, but a headless run cannot confirm audible output or a user-visible notification.
8 · Refresh failures and verification limits

Replay totals and challenge counters retained after a failed schedule refresh are labeled “Stale data” until a successful scan replaces them; a scan whose game feeds could not be fetched labels its totals incomplete rather than complete. Switching filters does not remove that warning. Historical automated checks compare rendered rows with the official MLB schedule and linked game feeds; they do not certify future data or restore missing original features.

9 · Reporting a problem

Consult MLB scores and Gameday for official results. If a value here disagrees with MLB, the page is wrong — every displayed data row links to the MLB response it came from so the two can be compared directly.
