What is verified, and against what

Every check below compares rendered output against a response fetched directly from MLB Advanced Media’s public StatsAPI. Nothing is marked verified without such a source, and where a value cannot be confirmed it is left blank and flagged here — never inferred or zero-filled.

  • Scoreboard — official schedule: team names, W-L records, scores, status pill, venue and probable pitchers are matched card by card (tests/verify_schedule.py).
  • Game view — official feed/live: header score and state, every linescore cell, every batting and pitching row, and every play description are matched cell by cell, each row carrying exactly one source link (tests/verify-game.mjs).
  • Replay Feed — official schedule plus each game’s linked feed: the scan covers every game the schedule does not report as Preview; every row names official team abbreviations; and every challenge counter shown is reproduced exactly from the official gameData.review / gameData.absChallenges fields. A counter MLB did not report is not displayed at all (tests/verify-reviews.mjs).
  • Official review fields. The Tigers–Rays feed exposes review results at both play and event level plus the reported replay and ABS counters, and MLB’s ABS highlight from that game identifies the overturned pitch challenge. The eventTypes registry contains os_ruling_pending_primary and os_ruling_pending_prior (“Official Scorer Ruling Pending”).
  • Archived World Series game. 2024-10-30 schedule — gamePk 775296, Dodgers 7 at Yankees 6, Final; full hydrate gives decisions.winner Blake Treinen and review counters home used 1 / remaining 1. These pin the archived game only.

Flagged irregularities

  • Exact parity with the original site cannot be proven. The upstream repository named by the inherited README, buffedlizard55-lab/MLB-Live-PBP, returns HTTP 404 through the GitHub API, so the true original cannot be compared against. Parity is instead anchored to the maintainer-identified working copy (LIVPBP2), whose HTML is byte-identical to this upload.
  • Live MLB data changes continuously. Every figure is point-in-time. Passing CI certifies the response the check downloaded, not any future response. An unavailable feed is not evidence that no review occurred.
  • Review classification is inference from reported codes. Rows are grouped using MLB’s reported reviewType and status codes; the ABS code (MJ) is confirmed against MLB’s own ABS highlight, other codes are shown as reported rather than given a more specific label. This classification is not an official MLB ruling field.
  • “Runs at risk” and the score trackers are computed, not reported. The Before / Possible-after tracker and the ⚠️ Runs-at-Risk banner are derived from the reviewed play’s own scoring movements. A “possible” score is explicitly not a prediction — on a boundary review MLB may instead place runners.
  • Team logo and headshot CDN. Images come from www.mlbstatic.com / img.mlbstatic.com. If an image fails to load the client hides it (onerror) rather than showing a broken icon, so a blocked CDN degrades to text only.
  • server.mjs is inherited, not run on GitHub Pages, and not reviewed as a service. It exposes an unauthenticated POST /api/feed-log accepting up to 50 MB with Access-Control-Allow-Origin: *, bound to 0.0.0.0 and without rate limiting, so anyone who can reach the port can write arbitrary JSON to data/. Static-file handling relies on path.normalize plus a prefix string check rather than path.relative. Run it on localhost/LAN only, or add authentication, before exposing it. GitHub Pages never executes it.
  • 404.html uses root-absolute /LIVPBP1/… URLs. Correct for this project page as deployed under snapquast73-boop.github.io/LIVPBP1, but a fork or rename must update those paths.
  • Public reuse of MLB data is not asserted here. The StatsAPI is a public endpoint but this page makes no claim about permission or terms for redistribution. The site is an unofficial fan project and states that it is not affiliated with MLB or MLB Advanced Media.
  • Unused files retained. tests/verify-game.mjs, tests/verify-reviews.mjs, tests/verify_schedule.py and tools/* are test assets, not shipped to the browser. data/ is git-ignored so optional server logs are never committed.

Reporting a problem

Consult MLB scores and Gameday for official results. If a value here disagrees with MLB, the page is wrong — every displayed data row links to the MLB response it came from so the two can be compared directly.

Refresh failures and verification limits

Replay totals and challenge counters retained after a failed schedule refresh are labeled “Stale data” until a successful scan replaces them. Switching filters does not remove that warning. Historical automated checks compare rendered rows with the official MLB schedule and linked game feeds; they do not certify future data or restore missing original features.
