How the site was restored (2026-11-22, sessions c0d0d08d & 774d0c87)

The original upload was incomplete. The uploaded snapshot (dad37b4, “Add files via upload”) contains only eight root files: index.html, game.html, reviews.html, 404.html, server.mjs, README.md, LICENSE, and .gitignore. Every module the pages load — assets/js/api.js, ui.js, reviews.js, feed-log.js, scoreboard.js, props.js, game.js, reviews-feed.js — plus assets/css/style.css, docs/, and tools/ were never uploaded. Earlier restoration attempts wrote a small stopgap client (assets/app.js) because the real modules were absent.

The full eight-module client and stylesheet were restored from the maintainer-identified working copy of this same project, snapquast73-boop/LIVPBP2, whose uploaded root blobs share identical SHA-1 hashes with dad37b4, while preserving concurrent reliability fixes (explicit stale and partial-scan warnings) and adding direct per-row official MLB source links across game.html, reviews.html, README.md, SOURCE-PROVENANCE.md, and docs/*.md.

What is verified, and against what

  • Scoreboard — official schedule: team names, W–L records, scores, status pill, venue, decisions, and probable pitchers are matched card by card (tests/verify_schedule.py, tests/official-e2e.mjs, and tests/live-e2e.mjs).
  • Game view — official feed/live: header score and state, every linescore cell, every batting and pitching row, and every play description are matched cell by cell, with each table row and review card carrying a direct link to its official MLB feed (tests/verify-game.mjs).
  • Replay Feed — official schedule plus each game’s linked feed: the scan covers every non-Preview game; every row names official team abbreviations and links to both game.html and its official feed/live URL; and every challenge counter shown matches gameData.review / gameData.absChallenges verbatim (tests/verify-reviews.mjs).
  • Archived World Series game. 2024-10-30 schedule — gamePk: 775296, Dodgers 7 at Yankees 6, Final; decisions.winner Blake Treinen, loser Tommy Kahnle, save Walker Buehler; postseason manager-challenge counters away used 0 / remaining 2, home used 1 / remaining 1.

Additional non-blocking notes & operational limits

  • Live MLB data is point-in-time. Passing CI certifies the official response fetched during the check, not future live updates.
  • “Runs at risk”, score trackers, and the Hit Forecast are computed, not official MLB fields. runsAtRisk binds strictly to runners[].details.isScoringEvent matching the reviewed event’s playIndex, and the Hit Forecast (assets/js/props.js) is a transparent log5 estimate, never an official MLB projection.
  • Polling cadences vs. inherited prose. Live modules poll at conservative intervals (10 s scoreboard, 5 s review watcher, 3–4 s active game / replay feed, paused when hidden) rather than sub-second intervals — see API Compliance.
  • Team logo and headshot CDNs. Images from www.mlbstatic.com and img.mlbstatic.com use onerror fallbacks so blocked images degrade cleanly to text.
  • server.mjs is local-only and never executed on GitHub Pages. It exposes an unauthenticated POST /api/feed-log (up to 50 MB, CORS *) writing to git-ignored data/. Run on localhost only.
  • The uploaded README's v1.0.0-stable-checkpoint tag does not exist. The uploaded README tells readers to reset to that tag for a stable baseline, but no such tag exists in this repository or in the source rebuild, so the instruction cannot be followed. The tag is not created here; creating release tags is a maintainer decision. Source checked: uploaded README (tree dad37b4).

Refresh failures and verification limits

Replay totals and challenge counters retained after a failed schedule refresh are labeled “Stale data” until a successful scan replaces them, and partial scans where one or more game feeds fail are labeled “Incomplete data”. Switching filters does not remove those warnings. Consult MLB scores and Gameday for official results.
