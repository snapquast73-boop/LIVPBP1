Still unverified / flagged

  • Exact original-client parity is unverifiable. The original demo repository named by the README, buffedlizard55-lab/MLB-Live-PBP, returns HTTP 404 through the GitHub API (re-verified 2026-11-20). Whether it is private, renamed or deleted cannot be determined. The restored client is a working functional equivalent from the owner’s own verified copy, not a byte-copy of any original client (none was ever recovered). Screens cannot be diffed against a dead upstream.
  • The v1.0.0-stable-checkpoint tag does not exist. The README’s checkpoint notice refers to it; no such tag has been found in this repository. Creating it is a maintainer decision.
  • Original polling cadences are unrecoverable. The original README describes 500 ms / 125 ms / 250 ms watcher loops. Those exact cadences cannot be recovered; the restored client polls at the budgeted intervals documented in docs/api-compliance.md. Function (live updates, review detection, alerts) is preserved; timing differs from the original description.
  • Sound & notifications require a user gesture. Browsers block audio until interaction, so a first-load chime can be silent until a click; the sound/notify toggles work as documented in the original README (raindrop chime, desktop notifications for run-at-risk reviews).
  • server.mjs (inherited from the upload, not run on GitHub Pages). Unauthenticated POST /api/feed-log accepting up to 50 MB, Access-Control-Allow-Origin: *, bound to 0.0.0.0 with no rate limiting: any website or machine that can reach the port can write arbitrary JSON logs to disk. Static-file path handling relies on path.normalize plus a prefix string check rather than path.relative. Recommend localhost/LAN-only use or authentication if exposed; flagged, not modified (it is the upload’s own file and GitHub Pages never runs it).
  • 404.html uses root-absolute /LIVPBP1/… URLs. Required on this project page as deployed under snapquast73-boop.github.io/LIVPBP1: a 404 can be served for any nested path, where relative URLs would break. Breaks only if the repository is renamed or forked to another base path — a fork must update those paths.
  • Point-in-time data only. Live MLB data changes continuously; all figures and snapshots are point-in-time observations. An unavailable feed is not evidence that no review occurred. Partial scans show only available rows and leave aggregate counts blank. Missing outcomes, descriptions or counter values stay blank and are flagged rather than zero-filled. Consult MLB scores and Gameday for official results.
  • Public data reuse permission is an open question. This is a personal, non-commercial fan project using the keyless public MLB StatsAPI; the two clauses that pull in different directions (the API’s own notice vs MLB.com Terms of Use) are written down in docs/api-compliance.md. Unverified whether public deployment is permitted; not blocking.
